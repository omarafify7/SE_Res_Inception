SE-Res-Inception V2

A custom CNN fusing Inception, Residual, and Squeeze-and-Excitation attention — trained from scratch on CIFAR-100.

8.86M Parameters

+18.6 pp vs. ResNet-18

The Problem

CIFAR-100 is a notoriously difficult image classification benchmark: 100 fine-grained categories (apple, bear, bicycle…) with only 500 training images per class at 32×32 resolution. At this low-data regime, standard CNNs overfit aggressively, and reaching the high 70s top-1 accuracy requires deliberate architectural and regularization choices.

Rather than fine-tuning a pretrained ImageNet model (transfer learning), this project asks: can we design an efficient CNN from first principles that beats ResNet-18 and GoogLeNet on CIFAR-100, trained from scratch, under identical conditions?

✅ Answer

Yes. A custom 8.86M-parameter network — fusing three well-established ideas — achieves 78.85% top-1, outperforming both baselines by a substantial margin at comparable or fewer parameters.

Three Ideas, One Architecture

SE-Res-Inception V2 composes three architectural mechanisms, each targeting a different failure mode of vanilla CNNs:

🔀

Inception Modules

Four parallel branches (1×1, 3×3, 5×5 convolutions and pooling) extract features at multiple receptive-field scales simultaneously, then concatenate. The network decides which scale matters per channel.

🔗

Residual Connections

Each block adds its output to the (projected) input. Gradients flow unobstructed through skip connections, letting us stack 9 Inception blocks deep without vanishing-gradient degradation.

🎯

Squeeze-and-Excitation

A tiny learned gate computes per-channel importance weights (global average pool → FC → sigmoid) and rescales each channel. This lets the network dynamically amplify informative channels.

The SE Block: Channel Attention Explained

The Squeeze-and-Excitation mechanism is the innovation that ties this architecture together. It's a lightweight attention module that recalibrates channels based on their global importance:

The key insight: instead of treating all channels equally, SE learns a small MLP that outputs per-channel multipliers. If channel 23 is "edge-like features pointing left," the SE block can dial it up or down based on what's globally in the image. The entire module adds less than 1% to parameter count but provides measurable accuracy gains.

SE(x) = x ⊙ σ(W2 · ReLU(W1 · GAP(x)))

Anatomy of a ResInceptionBlock

The core building block stacks 9 times throughout the network. Here's what happens to data passing through a single block:

Input: (B, C_in, H, W)
↓
Branch 1
1×1 conv
Branch 2
1×1 → 3×3
Branch 3
1×1 → 5×5
Branch 4
MaxPool → 1×1
↓
Concat along channel axis
↓
SE Block (channel attention)
↓
Dropout2d → DropPath
↓
+ Residual (projected if needed)
↓
Output: (B, C_out, H, W)

ℹ️ Why SE after concatenation?

A natural alternative is to apply SE per branch before concat. Putting it after concat is cheaper (one SE block per Inception, not four) and lets attention operate across all scales simultaneously — the gate can amplify the 3×3 output while suppressing the 5×5, or vice versa, as a single cross-scale decision.

The Regularization Stack

Five regularization mechanisms stack to prevent overfitting in the low-data CIFAR-100 regime:

🎨 Mixup

Blends two training images (and their labels) with a random mixing coefficient λ. Forces the network to learn smoother decision boundaries between classes.

✂️ CutMix

Cuts a rectangular region from image A and pastes it onto image B; labels mix proportionally to patch area. Encourages localized reasoning rather than global-average cheating.

🏷️ Label Smoothing

Replaces hard one-hot targets (1.0 for true class, 0.0 elsewhere) with soft targets (0.9 for true, 0.001 elsewhere). Prevents the network from becoming over-confident.

🪂 DropPath (Stochastic Depth)

During training, randomly drops the entire residual branch (block output → identity only) with a probability that increases linearly across depth. Forces robust features that survive block dropout.

💧 Dropout2d

Inside each Inception block, zeroes entire feature maps with probability 0.2 after SE. Prevents co-adaptation between channels.

⚖️ Weight Decay

L2 penalty of 5e-4 on all weights via AdamW. Keeps weight magnitudes small, acting as a prior toward simpler solutions.

Training Recipe

Optimizer:    AdamW (lr=1e-3, weight_decay=5e-4)
LR schedule:  Cosine annealing over 100 epochs
Batch size:   80
Precision:    Mixed (FP16 forward/backward, FP32 master weights)
Augmentation: RandomCrop(32, padding=4) + RandomHorizontalFlip
              50% of batches: Mixup(α=1.0) or CutMix(α=1.0)
Loss:         SoftTargetCrossEntropy with label_smoothing=0.1

These exact hyperparameters are used for all three networks (SE-Res-Inception, ResNet-18, GoogLeNet) to make the comparison rigorously fair — the only variable is the architecture.

ℹ️ Reading this table

SE-Res-Inception beats ResNet-18 by +18.6 pp top-1 while using 21% fewer parameters. It's slower per-inference (7.92 ms vs. 2.05 ms) because Inception branches don't vectorize as cleanly as ResNet's serial convolutions — a classic accuracy-vs-latency trade-off. For latency-critical deployments, ResNet still wins; for accuracy-critical ones, the custom architecture pulls ahead.

✅ When predictions are correct

Attention concentrates tightly on semantically meaningful object regions — the face of a seal, the petals of a poppy, the silhouette of a bee. This is visual evidence that the SE block has correctly identified the informative channels.

⚠️ When predictions are wrong

Attention is typically diffuse or mislocalized — scattered across background clutter, or fixated on non-discriminative features. The SE block's channel recalibration has latched onto the wrong signal; even a confident misprediction carries this interpretability signature.

Does It Scale? (Tiny ImageNet + COCO)

The same architecture — with a single-line stem adaptation for larger inputs — trains on three datasets of progressively larger scale:

DatasetInputClassesStem
CIFAR-10032×32100Conv 3×3, stride=1
Tiny ImageNet64×64200Conv 3×3, stride=1
COCO-Crops128×12880Conv 7×7, s=2 → MaxPool 3×3, s=2
Why the stem changes for 128×128

The body of the network was designed for 32×32 feature maps. Feeding it 128×128 directly inflates every downstream activation by 16× (128² / 32²), which at batch size 64 exceeds 16 GB of VRAM — the model would silently spill to system RAM and slow down 300×. The ImageNet-style stem downsamples the input by 4× before the Inception blocks, bringing spatial dimensions back to the regime the body was designed for.

if input_size <= 64:
    self.stem = nn.Sequential(  # CIFAR / Tiny ImageNet
        nn.Conv2d(3, 64, 3, stride=1, padding=1, bias=False),
        nn.BatchNorm2d(64), nn.ReLU(inplace=True),
    )
else:                           # COCO / ImageNet-scale
    self.stem = nn.Sequential(
        nn.Conv2d(3, 64, 7, stride=2, padding=3, bias=False),
        nn.BatchNorm2d(64), nn.ReLU(inplace=True),
        nn.MaxPool2d(3, stride=2, padding=1),
    )

Engineering Takeaways

Silent performance degradation is the worst failure mode

During COCO training, the model initially ran 300× slower than expected — without any error message. The root cause was the model's activation memory at 128×128 (33 GB) exceeding the 16 GB VRAM, and PyTorch silently spilling to system RAM via Windows unified memory. A crash would have been easier to debug. Lesson: for any new (model, input_size, batch_size) combination, benchmark in isolation and instrument peak memory explicitly before committing to multi-hour training.

Fair comparisons require discipline

The shortcut would be to evaluate against pretrained ImageNet baselines, but that's comparing "model trained from scratch on 50K images" vs. "model pretrained on 1.2M images then fine-tuned." Running baselines from scratch with identical hyperparameters cost 1.5 hours of GPU time and produced a defensible claim.

Hardware-software compatibility check first

The RTX 5070 Ti (Blackwell, SM_120) is incompatible with PyTorch stable builds through 2.6.x because those wheels don't include SM_120 CUDA kernels. This manifests only at runtime, not install time. Lesson: before any ML work on new hardware, verify with torch.randn(2,3).cuda().sum(). If it fails, install the nightly cu128 wheels.

Microservices aren't free — but they earn the cloud story

Splitting the single FastAPI server into Python inference + Go gateway added complexity: service discovery, cross-process error handling, healthchecks, depends_on orchestration. The payoff is a clear cloud-native architecture: CPU-heavy gateway on cheap Fargate, GPU inference on a separate EC2 instance, independently scalable. That separation is the main sell for platform-engineering roles.
